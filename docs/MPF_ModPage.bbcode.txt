[center][size=6][b]MODERN PHYSIQUE FRAMEWORK[/b][/size]
[i]Runtime face and body morphing for Skyrim NPCs[/i][/center]

[color=#e69138][size=5][b][u]- WHAT IT DOES[/u][/b][/size][/color]

Modern Physique Framework lets content mods give an NPC a named physique at runtime.
The same strength is sent directly to a face morph and a RaceMenu body morph, so the
head, nude body and compatible outfits change together.

[list]
[*][size=2]Applies face morphs over the FaceGen already loaded - vanilla or an NPC replacer[/size][/*]
[*][size=2]Applies the matching body morph directly through RaceMenu[/size][/*]
[*][size=2]Applies the same percentage to face and body while preserving NPC weight[/size][/*]
[*][size=2]Uses simple INI lists for NPCs and factions[/size][/*]
[*][size=2]Supports independent content mods, with deterministic priority rules[/size][/*]
[*][size=2]Refuses child races regardless of what an INI says[/size][/*]
[*][size=2]Ships no morphs or NPC list; installed alone, it changes nothing[/size][/*]
[*][size=2]Open-source SKSE plugin[/size][/*]
[/list]

[b]MPF does not regenerate FaceGen.[/b] It adds deltas to the live morph buffer, so an
NPC overhaul keeps its own sculpt, hair, tint and FaceGen. The morph is reapplied when
the game rebuilds that actor's 3D.


[color=#e69138][size=5][b][u]- ONE PERCENTAGE, TWO MATCHED MORPHS[/u][/b][/size][/color]

The number in an MPF list is one shared physique percentage. MPF applies it to the face
morph and the RaceMenu body morph. Skyrim's internal NPC weight is deliberately left at
its original value so its _0/_1 interpolation does not add a second neck deformation.

[code][NPCs]
Alvor  = 75, Heavy       ; 75% Heavy face/body morph
Narfi  = 95, Thin        ; 95% Thin face/body morph
Farkas = 90, Muscular    ; 90% Muscular face/body morph[/code]

A low number for [code]Thin[/code] means only a little of the Thin morph, not "very thin".
Use [code]auto[/code] to reuse the NPC's original record weight as morph strength.

[color=#e69138][size=5][b][u]- INSTALLATION[/u][/b][/size][/color]

Install MPF once, then install any content mod made for it. Do not merge or rename files
from different content mods. MPF reads every INI under:

[code]Data\ModernPhysiqueFramework\[/code]

and every morph manifest under:

[code]Data\SKSE\Plugins\MPF\morphs\[/code]

Higher [code]Priority[/code] wins when two files define the same NPC or physique. Ties are broken
by filename, so the result is stable and every conflict is written to [code]MPF.log[/code].

[b]Quick start:[/b] install MPF, then install one compatible content mod and all of that mod's
requirements. If the content mod ships BodySlide projects, build them; otherwise choose its
prebuilt option. Start the game normally - MPF needs no ESP and no one-time patcher.


[color=#e69138][size=5][b][u]- OPTIONAL IN-GAME CONFIGURATION[/u][/b][/size][/color]

With SKSE Menu Framework 3 installed, open [b]Modern Physique Framework / Configuration[/b].
The NPC tab only shows NPCs with an effective entry loaded from an INI, including
[code]MPF_User.ini[/code]. It shows the effective physique, strength and source mod. Use the
[b]Origin / mod[/b] filter to narrow the list to one source; it also finds that source's losing
conflict candidates, so you can inspect an override even when another priority currently wins.
A small conflict marker appears when more than one INI targets the same NPC; opening that row
lists every source and marks the active priority winner.

Editing or deleting a direct entry changes the INI that owns it. New NPCs with no existing
source go to [code]MPF_User.ini[/code]. A faction result can be converted into an individual user
override without changing the whole faction rule. The first edit creates a [code].mpf.bak[/code]
backup, and MPF reloads the configuration while the game remains open.

The Content tab lists sources, priorities and effective physique definitions. Settings contains
logging and manual reload/refresh controls. Runtime logging is saved separately under
[code]Data\SKSE\Plugins\MPF\settings.ini[/code], so it never rewrites a content mod just to change
a user preference. MPF still works normally when SKSE Menu Framework 3 is not installed.


[color=#e69138][size=5][b][u]- COMPATIBILITY AND NECK SEAMS[/u][/b][/size][/color]

Face replacers are broadly compatible. MPF identifies supported head meshes by sex,
vertex count and actual shape, then applies a morph authored for that topology. A head
with no matching morph is left alone.

[b]Body and outfit replacers need compatible morph data.[/b] A physique's [code]BodyMorph[/code] name
must exist in the [code].tri[/code] beside every nude body or outfit that can appear on that NPC. If
another mod replaces the body with a custom path and supplies no compatible morph, the
face can change while the body stays unchanged. The result is usually a neck seam.

MPF synchronizes face and body morph application, but it cannot fix incompatible assets. A
runtime plugin cannot invent missing body vertices or morph data, and face/body morphs
whose neck-ring deltas differ can still produce a seam.

Custom races and mods that give elderly NPCs, vampires or individual characters their
own body paths are the most common cases to check. They need an MPF-compatible patch,
or those NPCs should be omitted from the content mod's list.


[color=#e69138][size=5][b][u]- FOR CONTENT AUTHORS[/u][/b][/size][/color]

[b]1) Ship face morph TRIs[/b]

Place them in:

[code]Data\SKSE\Plugins\MPF\morphs\[/code]

Use unique filenames, preferably prefixed with your mod name. Every MPF content mod
shares this directory.

[b]2) Declare them in your own TOML manifest[/b]

[code][[sets]]
file = "MYMOD_FemaleHead.tri"
sex  = "female"          # male | female
part = "face"            # misc | face | eyes | hair | facialhair | scar | eyebrows[/code]

Name the manifest after your mod, for example [code]MYMOD_morphs.toml[/code]. MPF reads every TOML
recursively. The included [code]Docs\morphs.toml.example[/code] is a working starting point.

[b]3) Ship an INI in Data\ModernPhysiqueFramework[/b]

[code][Settings]
Priority = 200

[Physique.Heavy]
FaceMorph = RLY_Heavy
BodyMorph = RM_Heavy

[Physique.Thin]
FaceMorph = RLY_Thin
BodyMorph = RM_Thin

[NPCs]
Alvor = 75, Heavy
0x0001347F~Skyrim.esm = auto, Heavy

[Factions]
BanditFaction = 100, Heavy, 30%
BanditFaction = random, random, 30%[/code]

[list]
[*][size=2][b]FaceMorph[/b] is the exact morph name inside the face TRI[/size][/*]
[*][size=2][b]BodyMorph[/b] is the exact RaceMenu morph name inside compatible body and outfit TRIs; omit it only for a deliberately face-only physique[/size][/*]
[*][size=2][b]NPCs[/b] use an EditorID or [code]0xLocalFormID~Plugin.esp[/code], followed by strength and physique[/size][/*]
[*][size=2][b]Factions[/b] use strength, physique and an optional deterministic percentage. Either of the first two fields may be [code]random[/code]: strength then varies from 0 to 100 per NPC, while physique is chosen from every loaded definition. The two choices are independent and deterministic per NPC record. [code]random[/code] is faction-only.[/size][/*]
[*][size=2][b]Outfits[/b] assigns an exact replacement OTFT to a named NPC. It wins over the optional outfit-family fallback table at [code]SKSE\Plugins\MPF\outfits.ini[/code].[/size][/*]
[*][size=2][b]Priority[/b] resolves definitions and assignments without depending on file-system order[/size][/*]
[/list]

[code]BanditFaction = random, Heavy, 30%  ; random strength, fixed physique
BanditFaction = 60, random, 30%     ; fixed strength, random physique
BanditFaction = random, random, 30% ; both random[/code]

The SKSE Menu Framework faction editor exposes these as [b]Random strength[/b] and [b]Random physique[/b].

[b]Changing a deterministic random distribution[/b]

Faction share and [code]random[/code] choices are stable for a given NPC record, even after a save
reload or cell transition. To intentionally create a different distribution, change the non-negative
integer in [code]Data\SKSE\Plugins\MPF\settings.ini[/code]:

[code][Runtime]
RandomSeed = 1297100337[/code]

The same seed produces the same result. Changing it deliberately redistributes only faction rules
that use a percentage and/or [code]random[/code]; explicit [code][NPCs][/code] entries are unaffected.

[b]Two body routes for content packs[/b]

[color=#6aa84f][size=4][b]BODYSLIDE | runtime body morph[/b][/size][/color]

The content INI defines a [b]BodyMorph[/b], such as [code]RM_Heavy[/code]. The user builds
compatible body and outfit TRIs in BodySlide, then MPF asks RaceMenu to apply that morph at
runtime. This is the flexible route. It does [b]not[/b] need [code]outfits.ini[/code].

[color=#3d85c6][size=4][b]PREBUILT | fixed body meshes[/b][/size][/color]

The content INI defines only [b]FaceMorph[/b]. The content pack supplies ready-made body and
outfit meshes, then equips them through direct [b][Outfits][/b] and [b][Skins][/b] entries,
usually with an ESP that owns those records. MPF still changes the face at runtime, but there is
no BodySlide step and no runtime body morph.

[color=#e69138][b]About outfits.ini:[/b][/color] it is an optional generic MPF fallback table for
mapping a vanilla outfit to a replacement. It is not required by either route. It is useful only
when a content author wants MPF-managed NPCs with no direct [b][Outfits][/b] entry to receive a
replacement based on their vanilla default outfit:

[code][Outfits]
0x0001BCC0~Skyrim.esm = 0x00000804~MyPhysiqueMod.esp[/code]

Direct [b][Outfits][/b] entries always win over this fallback. Physiques of Skyrim's Standalone
package currently uses direct [b][Outfits][/b] and [b][Skins][/b] entries; its Full package leaves
[code]outfits.ini[/code] empty. In other words, [code]outfits.ini[/code] is an optional MPF feature,
not a required part of either Physiques of Skyrim route.

[b]There is no topology field.[/b] MPF reads the TRI's vertex count and compares its rest
shape with the live head. To support another head topology, author and declare another
TRI. An unsupported head is refused instead of receiving the wrong morph.

[b]BodyMorph is only a name, not body data.[/b] Your content package must also provide
compatible body/outfit meshes and TRIs containing that name, or require another package
that does. Test nude bodies and clothed torsos for both sexes and every custom body path
your NPC list can use.


[color=#e69138][size=5][b][u]- FILE LAYOUT[/u][/b][/size][/color]

[code]MyPhysiqueMod\
|-- SKSE\Plugins\MPF\morphs\
|   |-- MYMOD_FemaleHead.tri
|   |-- MYMOD_MaleHead.tri
|   `-- MYMOD_morphs.toml
`-- ModernPhysiqueFramework\
    `-- MyPhysiqueMod.ini[/code]

No FaceGen or scripts are required. An ESP is only needed if the content mod also adds
skins, outfits or other records.


[color=#e69138][size=5][b][u]- DIAGNOSTICS[/u][/b][/size][/color]

[list]
[*][size=2][b]F6[/b] reapplies MPF to the nearest actor[/size][/*]
[*][size=2][b]Shift+F7[/b] reports what would be applied to the nearest actor without changing it[/size][/*]

[b]Quick troubleshooting[/b]

[list]
[*][size=2][b]Nothing changes:[/b] make sure a content INI and its face-morph manifest are installed. MPF alone intentionally does nothing.[/size][/*]
[*][size=2][b]Face changes but the body does not / neck seam:[/b] the currently worn body or outfit is missing the configured [code]BodyMorph[/code] in its TRI. Build or install a compatible replacement.[/size][/*]
[*][size=2][b]Unexpected strength or physique:[/b] inspect the effective NPC entry and source in the optional configuration menu; a higher-priority INI may be overriding it.[/size][/*]
[*][size=2][b]Need support:[/b] include [code]Documents\My Games\Skyrim Special Edition\SKSE\MPF.log[/code] and say which NPC, body/outfit and head replacer were involved.[/size][/*]
[/list]

[b]Runtime support:[/b] MPF is built and tested on Skyrim SE 1.5.97. Other game runtimes are
not currently supported or promised.
